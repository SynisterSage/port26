# Portfolio Upgrade Phases (Target: 8.5+)

## Objective
Raise the portfolio from "good student" to "selective Product Design / UI-UX hire" quality.

## Baseline and Target
- Current strict score: `6.8 / 10`.
- Phase target score: `8.5+ / 10`.
- Expected lift if executed fully: `+1.3 to +2.0` points.

## Non-Negotiable Execution Rules
- Do not add new projects until flagship case studies are upgraded.
- Do not keep weak or redundant work on homepage.
- Every flagship must include measurable outcomes and explicit ownership.
- Portfolio, resume, and LinkedIn must use the same role language.

## Phase 1 - Reposition (Day 1-2)
- Set explicit role target above the fold: `Product Designer / UI-UX (2026 Graduate)`.
- Add immediate CTA block: resume, LinkedIn, email, "Open to full-time roles".
- Align summary language to product outcomes, not class context.

### Pass/Fail Gates
- PASS: role fit understood in 5 seconds by 3 test readers.
- PASS: clear value proposition in first viewport on mobile and desktop.
- FAIL: headline is generic or student-framed.

## Phase 2 - Curate Ruthlessly (Day 2-4)
- Keep 4-6 flagship projects on homepage only.
- Move all lower-signal work to archive and reduce visual prominence.
- Ensure each flagship maps to target role competencies.

### Pass/Fail Gates
- PASS: 100% of homepage projects support Product Design / UI-UX role fit.
- PASS: no duplicated skill signal across flagship set.
- FAIL: mixed-quality class work remains in prime placement.

## Phase 3 - Case Study Upgrade (Day 4-9)
Use this structure for each flagship:
1. Problem
2. Constraints
3. Role and ownership
4. Process and key decisions
5. Tradeoffs
6. Outcomes (with metrics)
7. Next iteration

### Required Proof
- At least 2 measurable outcomes per flagship where possible.
- At least 1 clear before/after comparison per flagship.
- Explicit tooling and collaboration scope.

### Pass/Fail Gates
- PASS: hiring manager can assess project quality in under 90 seconds.
- PASS: decision quality is visible, not only visuals.
- FAIL: pages read as polished summaries without evidence.

## Phase 4 - ATS and AI Parse Optimization (Day 9-11)
- Standardize hiring keywords: user flows, IA, wireframes, prototyping, usability testing, design systems, cross-functional collaboration, handoff, iteration.
- Add a plain-language Skills and Tools section.
- Align wording between portfolio, resume, and LinkedIn.
- Regenerate SEO/route artifacts after content updates.

### Pass/Fail Gates
- PASS: no conflicting dates, titles, or role labels across surfaces.
- PASS: keyword coverage appears naturally on homepage + case studies + resume.
- FAIL: role language mismatch between portfolio and resume.

## Phase 5 - Trust and Conversion (Day 11-14)
- Add top-level proof strip (3-4 credibility bullets).
- Add testimonial/client validation if available.
- Tighten contact flow and response expectation.
- Run final QA for mobile, links, media quality, and loading.

### Pass/Fail Gates
- PASS: contact path is one-click and obvious.
- PASS: no broken links, no unfinished sections, no low-res hero media.
- FAIL: friction remains in contacting or evaluating work.

## Validation Protocol (Mandatory)
Run this after each phase:
1. Recruiter skim test (5-second role fit, 30-second project fit).
2. Hiring manager skim test (90-second case study clarity).
3. ATS/AI consistency check (portfolio, resume, LinkedIn language alignment).
4. Technical QA (mobile, load speed, broken links, metadata).

## Scoring Rubric (Track Weekly)
Score each category 1-10:
- Positioning clarity
- Project curation quality
- Case-study depth
- Evidence and metrics
- ATS/AI keyword alignment
- Conversion readiness

## Expected Outcomes if Fully Executed
- Portfolio rating likely moves into `8.1-8.8` range.
- Better recruiter pass-through and stronger first-round interview conversion.
- Stronger positioning for selective Product Design / UI-UX opportunities.
